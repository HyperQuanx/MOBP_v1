Rest 방식 서비스

  • 클라이언트 중심
  • JSON 문자열
    • 키/값
  • REST 방식
    • 데이터를 전송하고 결과를 확인하는 방식
    • 효율적이고 안정적
    • 확장 가능한 분산 시스템을 설꼐 개발할 수 있는 소프트웨어 아키텍처들의 모임
    • REST 방식의 제약 사항을 준수하는 개발을 -RESTful하다- 표현.
  • 개발 URL 설계
    • 기존 ex)
      • /board/list
      • /board/view?idx=xxx
      • /board/update?idx=xxx
      • /board/delete?idx=xxx
    • REST 방식 ex)
      • /board GET방식
      • /board POST방식
      • /board PUT방식
      • /board DELETE방식
URL Method 설명 변환 데이터
/reply/regist POST 특정 게시글의 댓글 추가 생성된 글의 idx
/reply/list/idx/page GET 게시글의 목록 DTO를 JSON 처리
/reply/view/idx GET 댓글 내용 조회 댓글 객체를 JSON 변환
/reply/modify/idx PUT 댓글 수정 수정된 댓글 번호
/reply/delete/idx DELETE 댓글 삭제 삭제된 댓글 번호
  • JPA는 연관 관계의 방향성 결정이 어렵다.
  • 변화가 많은 쪽을 기준으로 연관 관계를 설정
  • ERD의 FK 기준으로 설정
  • 단방향
    • 한쪽만 참조를 유지
    • 객체 A가 B를 참조
    • 객체 B가 A를 참조
    • 구현 단순, 에러 발생 가능성 감소
    • 다른 쪽에 있는 엔티티 객체의 내용 사용이 어려워짐
  • 양방향
    • 양쪽 모두 참조를 하는 방식
    • 관리를 양쪽 객체에 동일하게 적용
